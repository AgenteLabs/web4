# web4.global — Web4 Global

The global community of agentic developers, as an institutional site: city
chapters, build nights, a builder track and answers, run as an accountable
organisation on the FlashyOS mesh. Everything under `site/` is generated by
`scripts/build.mjs` from the inputs beside it; there is no framework and no
dependency.

```bash
npm run build      # regenerate site/ from the inputs
npm test           # node --test — the drift suite, Node 22, no install
npm run check      # the vendored directory/1 and ritual/1 checkers
npm run survey     # fetch every listed chapter and write tally.json
npm run verify     # build, check, test
```

## What is here

| Path | What it is |
|---|---|
| `site.config.json` | The property: domain, parent, holder, accountable human, status line |
| `nav.json` | The one registry. Header, footer, sitemap and `llms.txt` render from it |
| `canon.lock.json` | `mesh.provenance`, `vocabulary.terms` and `open.door` as accepted from their owners |
| `flashyos.roles.json` | The AAO charter: eight roles, each one standing job, served at `/.well-known/flashyos-charter.json` |
| `directory.fragment.json` | `directory/1`, derived from the charter by `scripts/directory.mjs` |
| `ritual.fragment.json` | `ritual/1`, the calendar: two liturgies, observances appended by `observe()` |
| `tally.json` | The chapter survey's last reading. The only source of a chapter count |
| `content/` | Answers, glossary, the chapter register, the reading list |
| `brand/` | The Web4 Global kit, with `MANIFEST.sha256` and self-hosted fonts |
| `scripts/` | The generator, the pages, the derivations, the survey |
| `vendor-*.mjs` | Byte-identical copies from flashyos; re-vendor, never edit |
| `site/` | Generated output. Vercel serves it as committed (`vercel.json`) |

## Spinning this out to its own repository

The directory is self-contained by test (`test/spinout.test.mjs`): nothing in
it imports or reads a path above its root, its workflow lives inside it, and
its `vercel.json` serves `site/` with no build. To make it a repository of its
own, keeping history:

```bash
# from the web4 repository root, on its default branch
git subtree split --prefix=web4global -b web4-global-split
git push git@github.com:FlashyLabs/web4-global.git web4-global-split:main
```

Then on Vercel: import `FlashyLabs/web4-global`, Framework Preset *Other*,
Root Directory left at the repository root, Build Command empty, Output
Directory `site`; add the domain `web4.global` to the project. The three
drift tests that compare against sibling checkouts (`test/vendored.test.mjs`,
the conformance run in `test/charter.test.mjs`) report *UNKNOWN* when
flashyos and web4 are not checked out beside the new repository; that is the
designed answer, not a failure.

After the first deploy, the authoritative check is against the live domain:

```bash
npx @flashyos/conformance web4.global --level 2
```

## Rules

- **No figure is typed.** The chapter count is whatever `tally.json` last
  read, with its date. `test/figures.test.mjs` fails a page that carries a
  population figure nothing measured.
- **One owner per term.** The site says *Web 4* and links GDA Group's
  definition; it never restates one. `test/terms.test.mjs` fails a page that
  says a term and does not link its owner, and a source file that types a
  canonical URL the lock carries.
- **Agents suggest; humans consent.** No edge is countersigned and no
  observance consecrated by anything in this repository.
- **A generated file is regenerated.** `site/`, `directory.fragment.json` and
  `tally.json` are outputs. `test/build.test.mjs` fails a byte of drift.
